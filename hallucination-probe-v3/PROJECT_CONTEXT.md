## 1. Что это за проект (30 секунд)

Научная работа для конференции НТИ-2026 (секция 2.3). Гипотеза: по скрытым
состояниям LLM в момент перед генерацией ответа можно предсказать, что модель
сейчас ошибётся. Инструмент — линейные пробы (logistic regression) на
скрытых состояниях последнего токена запроса.

**Ключевое отличие от базовых методов:** базовые методы (энтропия, logprob,
самосогласованность 5 сэмплов) работают ПОСЛЕ или ВО ВРЕМЯ генерации ответа.
Проба работает ДО — по состояниям на входе в декодер. Это принципиально честное
сравнение «предсказание до ответа» против «диагностика после ответа».

## 2. Стек и датасет

- Модели: Qwen2.5-Instruct (0.5B / 1.5B / 3B) — open-weight, лицензия
  разрешает исследование, работает в Colab.
- Датасет: RuBQ 2.0 (2910 вопросов) → после фильтрации ~2300 вопросов.
  Двуязычный (ru/en), 7 тематик, своё разбиение 70/15/15 стратифицированное.
- Метрика: ROC-AUC с 95%-м доверительным интервалом (бутстрэп, 1000).

## 3. Пять вопросов исследования

В1. Есть ли сигнал в скрытых состояниях? (проба vs базовые методы)
В2. В каком слое он сильнее всего? (график AUC по слоям)
В3. Переносится ли проба между тематиками и языками? (train на одном,
    test на другом)
В4. Зависит ли эффект от размера модели? (0.5B vs 1.5B vs 3B)
В5. Адаптивный поиск: модель ищет в Википедии ТОЛЬКО при высоком риске.
    Кривая «точность vs доля вопросов с поиском».

### Модули (src/hprobe/)

| Файл | Назначение | Где запускается |
|------|-----------|----------------|
| `__init__.py` | Описание пакета | — |
| `prompts.py` | Единое место сборки промптов (ChatML, few-shot 2 примера). Критично: любое изменение промпта влияет на сопоставимость прогонов. | CPU |
| `data.py` | RuBQ 2.0 → questions.jsonl. Фильтрация (без no_answer/count/ranking/duration), infer answer_kind, домен из Wikidata-PROPs, стратификация 70/15/15. | CPU, один раз |
| `generate.py` | GPU-прогон. Жадный ответ + 5 сэмплов + скрытые состояния (float16, [N, L+1, d]). Левый паддинг. Resume при обрыве Colab. | GPU (Colab) |
| `label.py` | records.jsonl → labels.csv (верно/ошибка/отказ). Отделена от generate.py, чтобы правила можно было править без перепрогона GPU. | CPU |
| `labeling.py` | Правила «верно/ошибка». Нормализация + стемминг (snowballstemmer, lru_cache) + числа (2% допуск) + отказы. Частичные ответы = верны. | CPU |
| `probes.py` | Линейные пробы по слоям. Слой и C выбираются по val. Тест трогается один раз. Бутстрэп-ДИ. Сохраняет probe.npz для search.py. | CPU |
| `search.py` | Адаптивный поиск (В5). Проба оценивает риск → при пороге >= threshold добавляем абзац Википедии из RuBQ → перегенерация. Кривая по порогам. | GPU (Colab) |

### Тесты (tests/)

| Файл | Что проверяет |
|------|--------------|
| `test_labeling.py` | Разметка: имя/частичное имя, склонения, ё→е, год, число (2%), отказ, согласованность ответов. |
| `test_pipeline.py` | Сквозной прогон на крошечной случайной модели (3 слоя, 32 hidden). Проверяет: resume, левый паддинг (вектор не зависит от соседей по батчу), форму hidden.npy, разметку. |
| `test_probes.py` | Синтетика: сигнал заложен только в слой 3 → проба должна найти слой 3, val выбирает его, ДИ содержит test_auc. |
| `test_search.py` | Синтетика: кривая адаптивного поиска — границы, монотонность, точность растёт при отборе рискованных. |

## 5. Ключевые дизайн-решения и почему именно так

1. **Линейная проба, а не нейросеть.** Если линейный классификатор находит
   сигнал, информация лежит «на поверхности» скрытых состояний — это сильный
   научный аргумент. Мощный классификатор мог бы выдумать сигнал из шума.

2. **Тест трогается один раз.** Слой и C — по val. Бутстрэп 1000 на test.
   Никакого «посмотрели тест → перекрутили → посмотрели снова».

3. **Один факт — одна часть.** Вопрос с ru+en — одна строка в JSONL,
   разбиение по строкам. Иначе проба выучит факт на английском и «узнает»
   на русском — фальшивый перенос (В3).

4. **Стратификация по тематике.** Домен берём из свойств Wikidata в SPARQL
   (P36=столица → география), а не из текста вопроса. Объективно.

5. **Разметка отделена от генерации.** GPU-прогон — один раз. Правила
   проверки — правим сколько угодно за секунды.

6. **Левый паддинг.** В декодере каждый токен видит только предыдущие.
   Последний токен запроса — единственный, кто «знает» весь вопрос.
   С левым паддингом он на позиции -1 у всех в батче.

7. **НЕ сортируем по длине перед батчеванием.** Меньше паддинга = быстрее,
   но нарушает порядок questions.jsonl / records / hidden / labels.
   Скорость жертвуем ради корректности (тест test_pipeline.py).

8. **float16 для hidden.npy.** ~200 МБ/прогон вместо ~400 МБ. Потеря ~1e-3
   относительной точности — ниже шума самих активаций.

9. **Сэмплы: temperature 1.0, top_p=0.95.** Измеряем разброс модели
   «по умолчанию», но с небольшим усечением хвоста (top_p), чтобы
   сэмплы оставались грамматически приемлемыми.

10. **snowballstemmer + lru_cache.** Качественный стемминг для русского и
    английского с кэшированием 200k записей — быстро и точно.

## 6. Честность эксперимента (договорённости, которые нельзя нарушать)

- Слой выбирается по val_auc, тест — один раз.
- ДИ бутстрэпом 1000, seed фиксирован (42).
- Точность авторазметки измеряется ручной проверкой 100 ответов
  (manual_check.csv) и указывается в тезисах.
- Проба считается полезной ТОЛЬКО если побеждает базовые методы.
- Адаптивный поиск (В5) — абзацы ИЗ RuBQ (гарантированно содержат ответ),
  не живой поиск. Это потолок, а не обещание.

## 8. Как запускать

### Подготовка данных (CPU, один раз):
```bash
# Скачать RuBQ 2.0 в data/raw/:
#   RuBQ_2.0_dev.json, RuBQ_2.0_test.json, RuBQ_2.0_paragraphs.json
PYTHONPATH=src python -m hprobe.data
# → data/questions.jsonl (~2300 вопросов)
```

### Прогон в Colab (GPU):
```bash
PYTHONPATH=src python -m hprobe.generate \\
    --model Qwen/Qwen2.5-1.5B-Instruct --lang ru \\
    --out outputs/qwen2.5-1.5b/ru --batch-size 16 \\
    --n-samples 5 --max-new-tokens 24 --dtype bf16
# → outputs/qwen2.5-1.5b/ru/records.jsonl, hidden.npy, meta.json
```

### Разметка (CPU):
```bash
PYTHONPATH=src python -m hprobe.label --run outputs/qwen2.5-1.5b/ru
# → labels.csv, manual_check.csv
```

### Пробы (CPU):
```bash
PYTHONPATH=src python -m hprobe.probes --run outputs/qwen2.5-1.5b/ru
# → probe/summary.csv, probe/layers.png, probe/probe.npz
```

### Адаптивный поиск (GPU, В5):
```bash
PYTHONPATH=src python -m hprobe.search \\
    --run outputs/qwen2.5-1.5b/ru \\
    --model Qwen/Qwen2.5-1.5B-Instruct
# → search/curve.csv, search/curve.png
```

### Тесты (CPU, без GPU):
```bash
PYTHONPATH=src python -m pytest tests/ -q
```

## 11. Границы применимости (честно)

- Правила разметки — эвристика; точность автоматики измеряется ручной
  проверкой 100 ответов и указывается в тезисах рядом с результатами.
- `answer_kind` (entity/year/number/text) — эвристика по литералам RuBQ.

  Это и есть вопросы В3–В4, а не баг.
