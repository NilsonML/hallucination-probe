# hallucination-probe: знает ли нейросеть, что сейчас ошибётся?

Исследование: можно ли по внутренним состояниям языковой модели **до начала ответа**
предсказать, что ответ будет фактически неверным (галлюцинацией), и использовать это,
чтобы модель вовремя отказывалась отвечать или обращалась к поиску.

Секция 2.3 конференции НТИ-2026 (НГТУ).

## Вопросы исследования

| № | Вопрос | Эксперимент |
|---|---|---|
| 1 | Содержат ли скрытые состояния модели информацию о том, что она ошибётся? | Классификатор-проба на активациях последнего токена запроса против базовых методов: вероятность токенов ответа, энтропия, самосогласованность 5 сэмплов |
| 2 | На каком слое эта информация выражена сильнее всего? | Качество пробы (ROC-AUC) по каждому слою |
| 3 | Переносится ли проба на новые темы и на другой язык? | Обучение на одних тематиках → проверка на другой; обучение на английских вопросах → проверка на тех же вопросах по-русски |
| 4 | Как это зависит от размера модели? | Qwen2.5 0.5B / 1.5B / 3B |
| 5 | Какая практическая польза? | Адаптивный поиск: модель ищет в Википедии только когда проба предсказывает ошибку. Точность против доли обращений к поиску |

## Данные

[RuBQ 2.0](https://github.com/vladislavneon/RuBQ) (CC BY-SA 4.0): русскоязычные фактические вопросы
из Wikidata с допустимыми формулировками ответа, английскими версиями вопросов и абзацами Википедии.
После фильтрации (вопросы с ответом, не более 5 ответов, без подсчётов) — **2327 вопросов**,
7 тематик, разбиение train / val / test = 70 / 15 / 15, стратифицированное по тематике.
Один вопрос всегда в одной части для обоих языков.

## Как устроено

```
data/raw/                 исходный RuBQ 2.0 (dev + test)
data/questions.jsonl      подготовленные вопросы (python -m hprobe.data)
src/hprobe/
  data.py                 фильтрация, тематики, разбиение
  prompts.py              шаблон запроса: системная инструкция + 3 примера короткого ответа
  generate.py             ответы модели, сэмплы, признаки неуверенности, скрытые состояния
  labeling.py             правила проверки ответа (основы слов, годы, числа ±2 %)
  label.py                разметка прогона + выборка для ручной проверки
  probes.py               пробы по слоям, базовые методы, доверительные интервалы, график
  search.py               адаптивный поиск: проба решает, когда доставать абзац Википедии
notebooks/
  01_generate_colab.ipynb прогоны моделей в Google Colab
tests/                    тесты разметки и сквозной тест на крошечной модели
```

**Что сохраняет прогон** (`outputs/<модель>/<язык>/`):

| Файл | Содержимое |
|---|---|
| `records.jsonl` | вопрос, жадный ответ, 5 сэмплов, вероятности и энтропия токенов ответа |
| `hidden.npy` | скрытые состояния всех слоёв на последнем токене запроса, `[N, слои+1, d]`, float16 |
| `labels.csv` | правильность, отказ, самосогласованность, признаки базовых методов |
| `manual_check.csv` | 100 случайных ответов для ручной проверки разметки |

## Запуск

```bash
pip install -r requirements.txt
PYTHONPATH=src python -m hprobe.data                     # подготовка вопросов
PYTHONPATH=src python -m pytest -q tests                 # проверки
PYTHONPATH=src python -m hprobe.generate --model Qwen/Qwen2.5-1.5B-Instruct --lang ru --out outputs/qwen2.5-1.5b/ru
PYTHONPATH=src python -m hprobe.label --run outputs/qwen2.5-1.5b/ru
PYTHONPATH=src python -m hprobe.probes --run outputs/qwen2.5-1.5b/ru
PYTHONPATH=src python -m hprobe.search --run outputs/qwen2.5-1.5b/ru --model Qwen/Qwen2.5-1.5B-Instruct
```

Генерация требует GPU — используйте `notebooks/01_generate_colab.ipynb`.
